How this page finds its answer

This page is a single SQL statement. It does three things the database is far better at than Python would be:

  1. It computes the benchmark first. A common table expression aggregates every reporting country into one row — total cases divided by total population — giving the global rate.
  2. It uses that result to select a sub-dataset. The main query keeps a country only if country IN (SELECT …), where the inner query returns the countries whose own rate exceeds the scalar subquery (SELECT rate FROM global_stats). The result of the first query is what defines the second.
  3. It compares two datasets. A correlated subquery reaches from each infection row into the vaccination table for the matching country, year, disease and antigen, so reported disease burden and reported vaccination coverage arrive together instead of being stitched together afterwards.

Sorting and row limiting also happen in SQL. Fetching all {{ context.n_reporting }} countries into Python and sorting them there would move every row across the connection to display a handful of them, and would throw away SQLite's ability to use its indexes. The rows arrive already in their final order.

Reading this table honestly

  • High coverage and a high infection rate can coexist. Coverage is measured on one birth cohort; an outbreak can run through people who missed vaccination in earlier years.
  • A country only appears if it reported. Countries with weak surveillance may have high true rates and no row here.
  • “Above the global rate” is not a judgement of a country's health system. It is one ratio, in one year, for one disease.
